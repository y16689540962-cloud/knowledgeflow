# v0.4 · macOS Apple Silicon 一键安装版（设计与审计）

目标：让普通 Mac 用户**不打开终端、不装 Python、不配环境变量**就能用它完成第一篇 Obsidian 笔记。

## 一、审计结果（先查再写码）

| # | 审计项 | 结论 |
|---|---|---|
| 1 | Python 版本要求 | `requires-python = ">=3.11"`；本机开发用 3.13.12 |
| 2 | FastAPI 启动方式 | `backend/scripts/serve.py`（argparse + uvicorn） |
| 3 | serve.py 参数 | `--host --port --vault --mock --no-recovery --reload --no-web --expose` |
| 4 | 配置机制 | `.env` + pydantic-settings，共 18 个键（定稿 §25 的 17 个 + `DOUYIN_COOKIE`） |
| 5 | 数据库路径 | 默认 `sqlite:///./data/knowledgeflow.db` —— **相对 cwd**，见下面的坑 |
| 6 | Obsidian Vault | `OBSIDIAN_VAULT_PATH`；启动时校验目录存在 |
| 7 | 日志 | 只有 `StreamHandler(stderr)`，**没有文件日志**；现有 launchd 方案靠外部重定向 |
| 8 | ASR / OCR | faster-whisper（+ ctranslate2 / onnxruntime / av）+ pytesseract；**OCR 的真引擎是系统 tesseract** |
| 9 | LLM SDK | **没有 SDK**，直接 httpx 打 OpenAI 兼容的 `/chat/completions` |
| 10 | 测试 | pytest，离线（Mock LLM / MockTransport） |
| 11 | 已有 macOS 脚本 | `backend/scripts/install_autostart.sh`（LaunchAgent，非 GUI 应用） |
| 12 | Apple Silicon 兼容性 | **全部原生 arm64**（ctranslate2 / av / onnxruntime / numpy / Pillow / SQLAlchemy / PyYAML / tokenizers 实测 `file` 输出均为 arm64） |

### 审计推翻的两个 spec 假设

1. **FFmpeg 不是硬依赖。** 全仓库 `grep ffmpeg` 零命中，音视频解码走 PyAV
   （它的 wheel 自带 ffmpeg 库）。所以「FFmpeg 未检测到」不该出现在环境检查的
   阻塞项里 —— 实现里把它降级成一句说明。
2. **`DATABASE_URL` 是相对 cwd 的。** Finder 启动的 `.app` 工作目录是 `/`，
   这条相对路径会落到 `/data/`，必然写不进去。打包层一律改喂**绝对路径**
   （`DATABASE_URL` / `DOWNLOAD_DIR` / `HF_HOME` 三处）。

## 二、架构

```
KnowledgeFlow.app/Contents/
├── MacOS/KnowledgeFlow          ← 入口脚本：exec 内嵌 python 跑启动器
├── Info.plist                   ← LSUIElement=false（Dock 里能退出 → 发 SIGTERM）
└── Resources/
    ├── runtime/                 ← 内嵌 Python 3.13（python-build-standalone，可重定位）
    ├── launcher/kf_app/         ← 启动器（本目录上层的 packaging/macos/launcher）
    ├── backend/                 ← **原样的后端代码**（无 .env / 无 data / 无 tests）
    ├── packaging/               ← 依赖清单，排障时对照
    └── AppIcon.icns
```

数据与程序**严格分离**：

```
~/Library/Application Support/KnowledgeFlow/
├── config/settings.json   0600，含 API Key
├── data/knowledgeflow.db  + media/
├── logs/app.log, launcher.log
├── cache/huggingface/     Whisper 模型落这里，不污染 ~/.cache
└── runtime/service.json   进程状态（辅助信息，不作为判定依据）
```

### 为什么不是 PyInstaller

PyInstaller 要处理 FastAPI / pydantic / SQLAlchemy 的隐式导入，还要把
ctranslate2、onnxruntime、av 这些原生扩展塞进单文件。而**内嵌一个可重定位的
Python + site-packages** 有三个好处：

1. 后端代码**原样运行**，一行都不用改（这是本任务最重要的约束）
2. 出问题时可以用 `.app` 自带的解释器直接跑 `--check` / 手动跑 serve.py，可诊断
3. 不需要维护隐藏导入清单

代价是 .app 体积 269 MB（DMG 121 MB）—— 换来的是「装完一定能跑」。

## 三、启动器（`packaging/macos/launcher/kf_app/`）

| 模块 | 职责 |
|---|---|
| `paths.py` | 从 `Contents/` 推出全部路径；数据目录走 `Path.home()`（因此 `HOME` 可注入 → 能测「干净机器」） |
| `settings.py` | `settings.json` ↔ 后端 18 个环境变量的映射；`probe_llm` / `probe_vault` |
| `service.py` | 启动 / 探活 / 复用 / 关闭；单实例；孤儿处理 |
| `wizard.py` | 首次向导（osascript 原生弹窗）+ 环境检查 + 非交互模式 |
| `main.py` | 入口、子命令、信号处理 |

关键设计：

- **向导用 `osascript`**（`display dialog` / `choose folder`）。本机只有
  CommandLineTools、没 Xcode，自绘 Cocoa 界面会引入一堆构建依赖；而系统原生
  控件看起来更像「正规软件」。
- **判定「是否已在运行」只信 `/api/health`，不信 pid 文件。** 用户 `kill -9`
  启动器后后端可能还活着，pid 文件已无意义 —— 以探活为准才能既不复用错、
  也不起第二个。
- **`--stop` 找不到状态文件时用 `lsof` 找监听者**，杀完还要复查确实没了才敢说
  「已停止」。早期版本会在状态文件缺失时直接报成功（已修，有测试钉住）。
- **失败一律翻译成人话**：不弹 traceback，只给「XX 缺失 / 请检查 YY」+ 日志路径。
- 子进程用 `start_new_session=True` 自成进程组，退出时整组收掉。

## 四、取舍记录

- **ASR / OCR 随包内置**（269 MB），但**装失败只降级**、不中断构建（定稿 §19）。
  构建信息按**真实结果**记账：说「已包含」就必须能 `import` 验过
  —— 早期版本只看命令行开关，导致 BUILD-INFO 写「已包含」而 .app 里没有，已修。
- **ad-hoc 签名**（`codesign -s -`）。没有 Developer ID 就不假装有；README 写清
  首次打开要「右键 → 打开」，**不要求关闭系统安全功能**（定稿 §16）。
- **不做 Intel / Windows / Linux**（定稿 §1、§22）。后端本身跨平台，缺的只是打包层。
- **没做单实例的 IPC 锁**，用「探活 + 复用」代替：更简单，且天然处理孤儿。

## 五、已知限制

1. **未签 Developer ID、未公证**：首次打开需要右键放行一次；分发给别人时对方也会看到提示。
2. **`--minimal` 构建不含 ASR/OCR**：界面会如实显示未启用。
3. **OCR 依赖系统 tesseract**：未安装时自动停用（这是既有设计，非本次引入）。
4. **ASR 首次使用需联网下载模型**（约 500 MB，落在 `cache/huggingface/`）。
5. **启动器无法在无人操作下自动打开弹窗向导**：GUI 对话框不能用脚本点，
   所以向导的**界面路径**只能人工验一次；逻辑路径（非交互模式）有端到端测试覆盖。
6. 构建期依赖外网（pip）。国内网络需要 `KF_PIP_INDEX_URL` 指向镜像。

## 七、一次真实的 Clean Mac 实测

临时 `HOME` + 临时 Vault + 把 `.app` 拷进临时 `Applications/`，用**内置 runtime**
与**真实 LLM** 跑完整链路：

```
拷贝 .app 到 Applications     73.0s（脚本拷贝；真实拖拽是秒级）
双击 → 服务就绪               3.4s
导入第一条内容（真实 LLM）    5.9s → completed，6 claims
Obsidian 笔记落盘             KnowledgeFlow/Processed/15 分钟备好一周午餐….md（4393 B）
SIGTERM 关闭                  端口已释放，无残留进程
机器侧 Time to First Value    9.3s
```

用户侧还要加上：下载 DMG（取决于网速）、拖拽（秒级）、向导点三下（约 1 分钟）。
**远低于 10 分钟的验收线。**
