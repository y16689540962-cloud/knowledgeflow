# KnowledgeFlow Chrome 扩展

在抖音视频页点一下工具栏图标 → 当前链接被送到本地 KnowledgeFlow → 分析、结构化 → 写进你的 Obsidian 库。

## 装（一次性，30 秒）

1. 打开 `chrome://extensions/`，右上角打开 **开发者模式**
2. 点 **加载已解压的扩展程序**，选这个 `extension/` 目录
3. 建议点一下工具栏的拼图图标，把 KnowledgeFlow **固定**到工具栏

Chrome 每次启动会提示「请停用开发者模式运行的扩展」—— 那是未打包扩展的常态，
点「取消」保留即可（要彻底消除需要打包上架，那是另一件事）。

## 用

1. 确认本地服务在跑：`http://127.0.0.1:8000/api/health` 能打开
   （装了开机自启的话它自己就在跑）
2. 打开任意抖音**视频页**（地址栏里含 `/video/数字`）
3. 点工具栏的 KnowledgeFlow 图标 → 点 **采集并写入 Obsidian**
4. 等 5–30 秒（真实 LLM 分析），弹出结果：`completed` / `duplicate` + 笔记路径

同一条视频重复点 → 直接 `duplicate`，不重复烧 token、不重复写笔记。

### 在首页 / 推荐流上点会怎样

会明确告诉你「这是抖音的首页 / 频道页，地址里没有视频 id」，**不会**发请求、
也不会猜你在看哪一条。

为什么不去猜：实测抖音首页对新环境直接返回「验证码中间页」，DOM 里
一条视频链接都没有；就算偶尔能抓到，抓到的也大概率不是你正在看的那条，
而你**看不出它是错的** —— 静默采错比明确告诉你「请点开视频」糟得多。

这时候两个办法：点进具体视频再点图标，或者用抖音的「复制链接」把整段文案
粘进 popup 的输入框（后端会自动抠出里面的链接）。

## 它到底做了什么

只做一件事：**把当前标签的 URL 递给本地后端**。

抖音现在只吐 JS 壳页，页面里 `document.title` 是「抖音」甚至「验证码中间页」，
正文一个字都没有 —— 所以扩展不试着从页面里抠内容，那必然失败。
拿到 URL 之后全靠后端：短链解析 → `aweme_id` → 详情接口 → LLM 分析 → Obsidian。

也可以直接把抖音「复制链接」给的**整段分享文案**粘进输入框（后端会自动抠出链接）。

## 边界（要清楚）

- **需要本地服务常驻** —— 服务没起时扩展会明确提示，不会假装成功
- **只连 `http://127.0.0.1:8000`** —— `host_permissions` 里没有公网地址，也没有 `<all_urls>`
- 后端 CORS **只放行 `chrome-extension://`** 来源，不放行任意网页
  （任意网页能调的话，等于把「写你 Obsidian 库、用你 LLM 额度」开放出去）
- 但这也拦不住「你自己装的另一个扩展」—— 任何已装扩展都满足那个来源格式。
  服务只绑 127.0.0.1，把这个面缩到「本机能跑的东西」
- 改服务端口要同时改 `manifest.json` 的 `host_permissions`，否则浏览器会拦掉请求

## 文件

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3 清单（权限只申请 `activeTab` + `storage`） |
| `popup.html` / `popup.css` | 点图标弹出的面板 |
| `popup.js` | 取当前 URL → 探活 → 调采集接口 → 渲染结果 |
| `urlmatch.js` | URL 三态判定（与后端 `AWEME_ID_PATTERNS` 同口径，可被 node 单测真跑） |
| `icons/` | 工具栏图标：`icon.svg` 是**设计源**，PNG 由它渲染生成（1024px 出图后缩到 128/48/16） |

前端纪律与 `app/web/` 一致：不用 `innerHTML`、不用内联事件、不引框架、不加载远程代码。
这些都有测试钉在 `backend/tests/test_extension.py`。

> **商标说明**：图标是紫水晶切面，**意象上致敬 [Obsidian](https://obsidian.md)，不是它的官方 logo**，
> 本项目与 Obsidian.md 及字节跳动均无关联。改配色 / 形状请改 `icons/icon.svg` 后重新渲染。
